# AGENTS.md

本文档约束本项目（zeroexo_admin）中的 AI / 自动化开发行为。开发时优先遵循本文件，其次遵循用户当前消息。

## 基本原则

- 先读现有代码，再动手修改，优先沿用项目已有结构和写法。
- 写代码保持最少行数，能简单实现就不要引入复杂抽象，不要为假设的将来需求过度设计。
- 标准能力（协议、解析、加密、日期等）优先使用成熟库（antd、dayjs 等），不要手写底层实现。
- 不要改无关文件，不要顺手重构；只做任务明确要求的改动。
- 工作区已有用户改动时，不要回滚、不要覆盖，只在必要范围内追加修改。
- 本项目有 C 端页面，文案必须使用纯中文或纯英文，禁止中英文混合；禁止使用 emoji 图标。

## 开发闭环（每次需求必须走完）

**需求确认 → 分析定位（AI 定位，人确认方向）→ 实现 → 自检 → 本地 CR → 更新文档 → 提交**

- AI 负责快速搜索、缩小问题范围、执行已确认的规则；是否成立、兼容边界、CR 建议是否采纳等判断由人拍板。
- 改动完成后必须做**有边界的横向巡检**：按已确认规则（见 DESIGN.md）搜索全仓库同类实现是否一致，只输出候选问题与证据，不直接改码。

## 改动验收清单（每次改动后逐条打勾）

- [ ] 改动是否只包含任务所需内容（无无关重构/样式改动）
- [ ] 是否通过类型检查：`npx tsc --noEmit`
- [ ] 是否有边界情况未处理（空数据、超长文本、明暗主题、loading/disabled 状态）
- [ ] 新 UI 元素是否符合 DESIGN.md 规范（Modal centered 680px、搜索框 240、图标 @ant-design/icons、文案纯中文或纯英文）
- [ ] 是否与同类型既有实现保持一致（参考用户列表/资产列表等同款组件写法）
- [ ] 相关接口/常量改动是否已同步更新文档
- [ ] 跨文件一致性巡检：改动是否影响其他页面同类实现

## 技术栈

- React 18 + TypeScript + Vite + Ant Design 6 + @ant-design/pro-components + ECharts + i18next + react-router-dom
- 包管理：npm；后端独立在 `../zeroexo_backend`（NestJS + Prisma），接口前缀 `/admin/`

## 设计规范

- 全部 UI / 组件 / 数据规范以仓库根 `DESIGN.md` 为准，开发前先阅读相关章节。

## 反复提醒沉淀

- 如果开发中总是遇到某个问题，或用户反复提醒同一注意事项，必须把该注意事项写入 `DESIGN.md`（UI/规范类）或本文件（流程类），写成明确、可执行的规则，避免模糊描述。
